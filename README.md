# AIshukatsu

ローカルの Markdown ファイル群を **AI と人間の共通言語** として扱う就活管理アプリ。

正式な公開ドメインは [aishukatsu.net](https://aishukatsu.net/) です。今後のSEO・Search Console・公開記事URLはこのドメインを基準にします。

1 企業 = 1 フォルダ、各種メモは `.md` ファイル。データはすべてあなたの PC に残るので、そのまま Claude や Cursor 等の AI にフォルダを渡せます。ベンダーロックインなし。

## 特徴

- Googleログインは任意。選択したフォルダの文書と一覧を端末へ自動保存します。
- 一覧・選考ボード・カレンダー・ホームで同じ締切データを利用します。
- 文書はMarkdown、一覧は `データ/エントリー一覧.csv`。認証情報・追加シート・列設定は同フォルダの隠し保存ファイルに保持します。
- 書き込みを順番に実行し、保存失敗時は変更を保持して再試行できます。外部で変更されたファイルの上書きを停止します。
- ZIPでフォルダ全体を保存・復元できます。削除した文書はワークスペース内のゴミ箱へ移動します。
- クラウドへの一覧バックアップは手動、文書の自動保存は設定から有効にできます。ID・パスワードを含む一覧バックアップには暗号化の合言葉が必要です。端末内の隠し保存ファイルは平文です。

## フォルダ構成の例

```text
AI就活/
├── データ/
│   ├── エントリー一覧.csv
│   └── .エントリー一覧.meta.json
├── 企業名/
│   ├── 企業分析.md
│   └── ES・面接対策.md
├── 自己分析/
└── .aishukatsu-trash/
```

## 対応ブラウザ

ワークスペースのフォルダ操作は Chrome / Edge など **Chromium 系のみ**。Safari / Firefox は File System Access API 非対応です。公開マガジンの記事閲覧には、このAPIやログインは必要ありません。

## 就活マガジン

`/magazine/` に記事一覧・検索・カテゴリ絞り込み、`/magazine/<slug>/` に目次付きの記事ページがあります。原稿は `content/magazine/*.json` で管理し、下書きは配信しません。ビルド時に記事本文の静的HTML・構造化データ・サイトマップを生成します。

記事の作成・公開手順は [マガジン運用ガイド](docs/magazine-publishing.md) を参照してください。

ブラウザのトップ `/` は常に紹介サイトを表示します。Web版の管理アプリは `/app/` から開きます。既存のログイン状態と保存フォルダを引き継ぎ、デスクトップ版の起動先は従来のままです。

## 開発

```bash
npm ci         # Node.js 22.12以上（CIは24）
npm run dev    # http://localhost:5173
npm run build  # 公開Webサイトとマガジン
npm run build:desktop  # 記事データを含めないデスクトップ用画面
npm run tauri:dev
npm run test:app
npm run test:routing
npm run test:analytics
```

## 0.2.19の検証と配布

保存順序・失敗後の再試行・終了直前の保存・CSVとメタデータの部分的な書き込み失敗・外部編集との競合・アカウント分離・取込日付・認証コールバック・HTML表示・ZIP復元を回帰テストで確認します。

MacとWindowsのCIで回帰テスト・デスクトップ用画面のビルド・Rustのコンパイルを実行します。リリース用ワークフローは下書きを作成し、署名・公証・実機確認の結果を記載してから公開します。Windows x64・ARM64とMacの配布ファイルを、Webページから選択できます。

新しいデスクトップ認証フローは `desktop-auth-v2.html` とアプリ双方で認証状態を照合します。旧アプリ向けの `desktop-auth.html` は保持します。配布前にWeb側の新しい認証ページも公開してください。Windows実機でのインストール・Googleログイン・更新の確認と、署名付きインストーラーの公開は別途必要です。

## アプリ内の自動更新

Mac・Windows版の画面下部、またはアプリメニューの「アプリの更新を確認」から更新できます。ログイン前やフォルダ選択前も利用できます。起動時と定期的に更新を確認し、ダウンロード中は画面を閉じて作業を続けられます。「更新して再起動」で保存を完了してから適用します。保存できない場合は更新を停止し、ダウンロード済みのファイルを保持します。

配布には既存の更新用署名鍵を使用します。署名と署名対象のバージョンを検証し、Mac Apple Silicon・Intel、Windows x64・ARM64の全ファイルが揃った後に更新情報を公開します。更新メニューやインストール処理の秘密鍵・パスワードはアプリに含めません。

リリースはバージョンタグで実行します。手動実行では公開前の下書きも作成できます。全プラットフォームのビルドと署名検証が成功するまで、公開中の更新情報は置き換えません。回帰確認は `npm run test:updater`、配布ファイルの確認は `node scripts/updater-release.mjs DIRECTORY VERSION` で実行します。

MacのWebViewでアニメーションが停止しても更新・確認ダイアログを表示・終了できるよう、共通ダイアログの開閉はアニメーションの進行を待たずに行います。
